5. 背景图 / Banner 处理（本文重点之一）

站点一共用到三处图片，作用不同、尺寸要求也不同：

配置项 作用范围 建议尺寸 实际做法

avatar.img 头像（圆形显示） 正方形 400×400

5.1 图片放哪

统一放 source/img/，Hexo 会原样复制到 public/img/，页面里用 /img/xxx.jpg 引用。

5.2 处理思路（三条经验）

  1. 原图往往太大：相机/NASA 原图 2000×1867、6.4 MB 这种，直接引用会让首屏加载十几秒。目标压到 300—700 KB。
  2. 必须裁剪，不能只缩放：Banner 区域是宽屏，近正方形的图会被 CSS 裁掉上下（background-size: cover），与其让浏览器乱裁，不如自己按 16:9 裁好，保证主体居中。
  3. 裁剪锚点要看图：银河/星野类图片主体通常在中上或中下，居中裁可能把主体切掉。例如银河带在图片高度 13% 处时，用顶部对齐裁（从 y=0 开始）比居中裁更好。

6.5 首页副标题打字机

两个关键点：

  1. typed_option 是覆盖 typed.js 的默认参数。主题模板里写的是
    Object.assign({typeSpeed:150, backSpeed:50, loop:true, startDelay:300}, <你的typed_option>)，
    所以页面源码里永远能看到 typeSpeed: 150——那是左侧默认值，你的参数在右侧对象里才生效。判断是否生效要看右侧。
  2. sub 里要显示多行，字符串必须用双引号（YAML 单引号里的 \n 是字面反斜杠 n，不会被解析为换行），并且要配一条 CSS，否则 HTML 会把换行符当空格吃掉：

9.3 中文标题的 URL

permalink 的 :title 取自文件名（不是 front-matter 的 title）。所以：

  • 文件命名用 ASCII：print-hello-world.md、ji-xue-xiao-sheng-qi.md
  • 页面里显示的仍是 front-matter 里的中文/符号标题
  • 最终地址：/2026/10/26/print-hello-world/

首选 Office COM 工具（本机有 mcp__office__*）。若不可用，docx 本质是 zip，可以直接解 XML：

  • 图片可能是 VML（<v:imagedata>）而非 DrawingML（<a:blip>），判断位置时两种都要查

10.2 还需要你做的（需要联网 + 你的账号）

  1. 在 GitHub 建仓库：名字必须是 fwind-hidden.github.io（用户主页仓库），不要勾选初始化 README。
  2. 配置推送认证（二选一）：
    • PAT：GitHub → Settings → Developer settings → Personal access tokens，勾 repo 权限。推送时用户名填 fwind-hidden，密码填 token。
    • SSH：ssh-keygen -t ed25519 -C "<你的邮箱>"，把 ~/.ssh/id_ed25519.pub 加到 GitHub → Settings → SSH keys；然后把 deploy.repo 改成 git@github.com:fwind-hidden/fwind-hidden.github.io.git。
  3. 发布：
  4. GitHub 仓库设置：Settings → Pages → Source 选 Deploy from a branch → 分支 gh-pages → / (root) → Save。等 1—2 分钟，访问 https://fwind-hidden.github.io。
  5. 源码备份（强烈建议）：把 main 分支（源码）推到另一个私有仓库，例如 fwind-hidden.github.io-source： 否则生成物一覆盖，源码就只剩本地一份。

  • 记得每次改完：hexo clean && hexo generate && hexo deploy

11. 报错速查表

编号 症状 根因 解决
E01 npm.ps1 / hexo.ps1 cannot be loaded because running scripts is disabled PowerShell 执行策略禁脚本 改用 npm.cmd / hexo.cmd，或 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
E02 schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e) Windows SChannel 在受限环境下取不到凭据；网络本身正常 git config --global http.sslBackend openssl
E03 ERR_PNPM_IGNORED_BUILDS ... Ignored build scripts: hexo-util 新版 starter 自带 pnpm 配置，pnpm 默认拦构建脚本 删 pnpm-lock.yaml pnpm-workspace.yaml node_modules 后改用 npm
E04 npm warn install-scripts ... hexo-util (postinstall: npm run build:highlight) npm 11 的 allowScripts 机制默认拦 postinstall npm.cmd install-scripts approve hexo-util
E05 EPERM: operation not permitted, mkdir 'D:\...\.github' / Error: D:/.../.git: Permission denied 目标目录在文件沙箱允许范围之外 放宽该目录写权限（或把站点建在工作区/用户目录内）
E06 改了 _config.yml，页面还是旧标题/旧作者 hexo s 不热更新站点主配置和 scripts/ 重启 hexo s；_config.butterfly.yml 和文章改动才自动热更新
E07 控制台里中文全是 ������，文件名显示 ��� 控制台按 GBK 解码 UTF-8 读文件时显式 -Encoding UTF8；Python 前设置 $env:PYTHONIOENCODING='utf-8'；不要据此判断文件损坏
E08 YAML 解析异常 / 页面首行多出怪字符 PowerShell Set-Content -Encoding utf8 写了 BOM 用 [IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding($false)))
E09 Template render error: TypeError: Cannot read properties of undefined (reading 'posts') 自定义 tag 里用了 this.site，页面渲染上下文里没有 改用模块级 hexo.locals.get('posts').toArray()
E10 页脚永远是亮蓝色 #49b1f5，深色模式下也不变 主题 footer.styl 写死 background-color: $light-blue，无配置项 inject.head 注入 #footer{background-color:...!important}
E11 改了 typed_option 但速度没变 主题模板里 Object.assign(默认值, 你的参数)，页面上仍能看到默认值 检查覆盖对象（Object.assign 第二个参数）里是否是你的新值
E12 sub 里写了 \n 但不换行 HTML 把换行符折叠成空格 配 #subtitle { white-space: pre-wrap; }；YAML 用双引号
E13 中文文章 URL 变成一长串 %E5%BF%8D... :title 取自文件名 文件名用 ASCII，标题写在 front-matter 里
E14 hexo g 卡很久 / docx 体积巨大 文章内嵌图是 4608×3456 原图 压到宽 1600、JPEG 质量 85
E15 用编辑器打开 .md 看不到图 写的是站点绝对路径 /img/... 本地查看时临时改相对路径 images/...；博客里保持 /img/...
E16 后台预览服务突然消失 沙箱里的后台进程随会话结束被回收 重新 hexo.cmd server -p 4000
E17 首页没有任何文章 source/_posts 为空 至少放一篇 .md，或别删光示例文章
