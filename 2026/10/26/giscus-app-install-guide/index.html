安装 Giscus App：一步步把评论区跑通

发表于2026-10-26|更新于2026-10-26|技术
|总字数:998|阅读时长:3分钟|浏览量:

上一篇记录了 Giscus 在 Butterfly 里的配置。但配置完只是”页面上长出了评论区”，离真正能发评论还差最后一步：安装 GitHub App。这篇只讲操作链路，每一步说清点哪儿、看到什么、失败长什么样。

一、先理解：这里有两层授权

很多人卡住，是因为把两件事当成了一件：

层级 谁来做 授权对象 作用
App 安装 仓库主人（你，一次） 仓库 允许 giscus 读写这个仓库的 Discussions
个人授权 每个评论者（首次） 自己的 GitHub 账号 允许 giscus 代表他发评论

你只需要做第一层。第二层由读者在点「登录」时自己完成。

两层都没做时，评论区显示的是 giscus is not installed on this repository——这个报错只跟第一层有关。

二、操作链路

步骤 1 · 打开 App 页面

先确认右上角登录的是仓库所属账号。登录错账号是后面所有失败的头号原因。

步骤 2 · 点 Install

页面右上角绿色 Install 按钮。

如果这里显示的是 Configure，说明已经装过，直接跳到步骤 5 检查范围。

步骤 3 · 选择安装位置

GitHub 要求 App 装在”账号或组织”上，不是直接装在仓库上：

  • 仓库属于个人 → 选个人账号
  • 仓库属于组织 → 选组织

选错的话，下一步的仓库列表里根本搜不到你的仓库。

步骤 4 · 限定仓库范围（唯一容易出错的一步）

进入 Install giscus 配置页，找到 Repository access：

选项 建议
All repositories 不选（等于授权给你所有仓库）
Only select repositories 选它，然后只勾目标仓库

下拉框支持输入仓库名搜索。勾完点绿色 Install。

这一步没勾上仓库，后面一定报 not installed——而且安装页已经”成功”跳走了，很容易误以为装好了。

步骤 5 · 核对安装结果

两个入口任选其一：

正确的状态：Only select repositories (1)，且列表里就是你的博客仓库。

步骤 6 · 看评论区的变化

打开任意文章页，滚到最底部：

显示 含义
红色 giscus is not installed on this repository 步骤 4 没勾上仓库，回去重配
Sign in with GitHub 按钮 安装成功
一片空白 多半是缓存，强制刷新（Ctrl+F5）

步骤 7 · 发第一条评论

  1. 点 Sign in with GitHub
  2. 弹出 GitHub 页面 → 点 Authorize giscus（这是第二层授权，代表”你自己”）
  3. 回到页面，出现输入框
  4. 输入内容，提交

步骤 8 · 确认评论存到了仓库

应该多出一条讨论，标题就是文章路径（配置里 data-mapping: pathname 的效果）：

每篇文章对应一条讨论，所以改文章标题不会重复建讨论。

三、卡点速查

现象 原因 处理
只有 Configure 没有 Install 之前装过 去 Configure 检查范围
仓库下拉搜不到博客仓库 登录账号或安装位置选错 确认账号，重选安装位置
装完仍报 not installed 范围没勾上目标仓库 回 settings/installations 重配
点登录后反复跳回 浏览器拦第三方 Cookie 放行 giscus.app
评论提交成功但页面不显示 iframe 缓存 等 30 秒或强刷
讨论建到了错误的分类 category_id 不对 用 GraphQL 重新取分类 ID

四、小结

Giscus 的配置量其实很小，真正的时间都花在三件事上：装 App 时有没有勾对仓库、两层授权有没有分清、报错是不是真的来自 App 未安装。把这三件事拆开看，剩下的都是复制粘贴。
