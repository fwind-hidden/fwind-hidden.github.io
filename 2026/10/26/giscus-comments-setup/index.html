用 Giscus 给 Hexo + Butterfly 博客加评论系统

发表于2026-10-26|更新于2026-10-26|技术
|总字数:864|阅读时长:3分钟|浏览量:

GitHub Pages 只托管静态文件，没有数据库，所以评论必须”存在别处”。这篇记录本站接入 Giscus 的全过程，含踩坑点。

一、四种方案怎么选

方案 评论存在哪 需要后端 登录方式 适用
Giscus 仓库 Discussions 否 GitHub 推荐，读者有 GitHub 账号即可
Utterances 仓库 Issues 否 GitHub 界面朴素，把评论当 issue 管理
Waline 自建数据库 是（Vercel/LeanCloud） 微信/匿名/邮箱 不想让读者登录 GitHub
Twikoo 自建数据库 是 微信/QQ/邮箱 功能最全，部署最麻烦

本站选 Giscus：零后端、零费用、和站点同仓库、支持暗色模式自动切换。

二、原理

Giscus 是一个 GitHub App + 前端脚本：

  1. 页面加载时插入一段 <script src="https://giscus.app/client.js">
  2. 脚本按 data-mapping 规则把当前页面映射成一个 Discussion
  3. 读写评论全部走 GitHub API，权限就是读者自己的 GitHub 账号

所以它需要的配置就是：仓库、仓库 ID、分类 ID、映射方式。

3. 写 Butterfly 配置

改 _config.butterfly.yml：

两个要点：

  • option 里的键会原样变成 giscus 脚本的 data-* 属性，所以键名必须用带 data- 前缀的写法
  • light_theme / dark_theme 对应站点的明暗模式，Butterfly 会在切换主题时通过 postMessage 通知 iframe 换肤，不需要刷新

4. 生成并发布

5. 装 GitHub App（最容易漏）

打开 https://github.com/apps/giscus → Install → 选择你的仓库。

没装的话评论区会直接报 giscus is not installed on this repository，前端看起来”加载了但用不了”。

四、验证

  • 文章页源码里应有 #giscus-wrap 容器和 giscus.app/client.js
  • 用 pathname 映射时，每篇文章自动对应一个讨论，改标题也不会重复建讨论
  • 首次有人评论后，仓库 Discussions 里会出现对应条目

五、踩过的坑

现象 原因 解决
全站 404 仓库推送了但 GitHub Pages 没开 Settings → Pages 选 gh-pages 分支，约 60—90 秒生效
评论区空了 只填了 repo，没填两个 ID ID 必须用 GraphQL 查，REST 拿不到
评论框不出现 comments.use 写成 giscus 必须首字母大写 Giscus
换肤后颜色不对 只配了一个主题 light_theme 和 dark_theme 都要配
评论数永远是 0 开了 lazyload 关掉 lazyload

小结

Giscus 的配置量不大，真正容易卡住的是三件事：Pages 有没有开、两个 ID 有没有用 GraphQL 拿对、App 有没有装。把这三步做完，剩下的就只是贴一段 YAML。
